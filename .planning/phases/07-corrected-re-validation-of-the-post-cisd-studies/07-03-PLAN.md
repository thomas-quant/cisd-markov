<objective>
Produce and publish the corrected evidence. With the reversal tags (07-01) and the verdict script (07-02) in place, regenerate the full validation manifest end-to-end — discovery, sacred OOS, and walk-forward — against the real NQ/ES data (RES-05), run the D-09 verdict script on the regenerated manifests, run the D-10 sanity check on the 14 pre-existing analyses, and hand-author the new README go/no-go section (D-08) plus the D-04 transparency disclaimer from the script-generated numbers (D-09).

Purpose: The two post-CISD studies have never been fully validated — the on-disk OOS manifest predates them, so all 160 of their bucket-rows currently read "not-confirmed" purely because OOS data is absent, not because they failed. This plan closes that gap under the corrected methodology and issues the explicit per-tag go/no-go verdict that strictly gates Phase 8's modeling decision.

Output: three regenerated manifests; a rebuilt findings table; two verdict CSVs; a new README section + disclaimer.

NOTE ON RUNTIME (env-gotchas + pacing convention): each build_validation.py run against real data takes ~20 min single-threaded (~60 min for all three), and the full test suite is ~22-28 min. ALL commands MUST use the .venv interpreter (`.venv/bin/python`, pandas 3.0.2 — system python3 changes the numbers). Run sequentially on the main tree; git-worktree isolation is unsafe here because data/*.parquet and .venv/ are gitignored. State this cost up front and do not wrap the long jobs in polling loops.
</objective>
