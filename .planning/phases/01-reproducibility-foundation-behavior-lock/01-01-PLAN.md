<objective>
Make the engine reproducible on a fresh machine and remove the hardcoded, machine-specific SMT dependency as a hard failure. Pin the runtime in a manifest, read the SMT package location from an environment variable with a documented default, make the main CLI degrade gracefully when SMT is absent, and bring build_forward_returns.py to parity with build_expectancy.py so every entry point degrades gracefully when SMT is unavailable.

Purpose: Reproducibility is the foundation for everything downstream — the validation harness and refactor cannot be trusted if the environment is not pinned and entry points crash on machines without the proprietary SMT path. The phase goal is "reproduces deterministically on any machine"; that means the headline command python3 cisd_analysis.py must not crash on a checkout that lacks the SMT package.
Output: requirements.txt, .env.example, an env-var-driven SMT path plus a graceful smt_cisd skip in cisd_analysis.py, a graceful SMT fallback in scripts/build_forward_returns.py plus its regression test, and updated README docs.

Behavior-preserving constraint: This plan MUST NOT change any computed number. The pinned versions are the EXACT versions already installed in the project .venv (pandas 3.0.2, numpy 2.4.4, matplotlib 3.10.8, pyarrow 23.0.1, pytest 9.0.2) — pinning what is already running cannot move a result. The graceful skips only trigger when SMT is ABSENT (where there is no number to preserve); when SMT resolves, behavior is byte-identical. If a pin must differ from the installed version for any reason, STOP and surface it rather than upgrading.
</objective>
