<objective>
Add walk-forward (rolling-window) validation to the harness, satisfying WF-01. The single sacred discovery/OOS split still runs unchanged; walk-forward supplements it by re-confirming each edge across multiple sequential train→test windows carved entirely from the discovery region. Windows are expanding/anchored (D-05) with 4 frozen calendar-date fold boundaries (D-06), all strictly before OOS_START so the one sacred OOS look is never consumed a second time (D-04). The aggregate robustness verdict requires a majority (>50%) of test folds to pass (D-07).

Purpose: An edge that held on one fixed holdout might be luck; walk-forward makes robustness the harder bar — it must hold across most sequential windows. This is the walk-forward half of Phase 6.
Output: A `--walk-forward` CLI flag and a new sibling artifact `output/validation_manifest_walkforward.csv` recording per-fold pass/fail and a per-bucket aggregate robustness verdict, a frozen `WALK_FORWARD_FOLDS` constant, fold-slicing/evaluation/aggregation helpers with characterization tests, and a README methodology section. The discovery/OOS manifests and all existing numbers are untouched.
</objective>
